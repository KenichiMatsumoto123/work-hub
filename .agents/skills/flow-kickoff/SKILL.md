# flow-kickoff: 開発開始の受付（要件の受け取りと深掘り）

10フェーズフロー（`docs/開発プロセス/設計から実装までのフロー.md` 参照）の**前段**を担当する skill。要件が固まっていない状態で設計・実装に突入することを防ぎ、Phase 1 の入力となる**要件メモ**を整えるのが責務。

**Phase 8 との混同に注意：** 「実装したい」という言葉が含まれていても、設計書・承認済みテストがまだ存在しない**新規開発の開始合図**は本 skill が受ける。`flow-phase8-impl`（「実装して」）は Phase 7 承認済みのテストを通す実装フェーズであり、別物。

## 実行手順

### Step 1: 要件の提示を求める

ユーザーに対象機能の要件を提示してもらう。形式は自由（箇条書きメモ・利用フロー・画面モック・既存資料のパス等）。何を出せばよいか迷わないよう、最低限の例を添える：

- 何を実現したいか（目的）
- 誰が使うか（利用者）
- 主な操作・画面のイメージ
- やらないこと（分かっていれば）

依頼文にすでに要件が含まれている場合は、その内容を要約して確認し、Step 2 へ進む。

### Step 2: 深掘り（grilling）の要否をユーザーに選択させる

提示された要件に対して、次の選択肢を提示して**ユーザーに選ばせる**（勝手に深掘りを始めない）：

1. **grilling で深掘りする**（推奨：要件が粗い・新規性が高い・影響範囲が読めない場合）→ Step 3 へ
2. **深掘りせずこのまま進む** → Step 4 へ

### Step 3: grilling による深掘り（選択時のみ）

提示された要件を対象に `grilling` skill を起動し、前提・スコープ・受け入れ条件の種を質問攻めで掘り起こす。

**grilling skill が未導入の場合**：その旨と導入コマンドを案内する：

```bash
npx skills add https://github.com/mattpocock/skills --skill grilling
```

導入せずに進む場合は、grilling の手法に準拠した**簡易深掘り（フォールバック）**を司令塔自身が実施する。

**進め方の原則（grilling 準拠）：**

- 提示された要件の**あらゆる側面について、共通理解に達するまで徹底的に質問する**。設計判断の木を枝ごとに辿り、判断同士の依存関係を1つずつ解決していく
- **質問は必ず1問ずつ**提示し、回答を待ってから次に進む。複数の質問を同時に投げることは混乱のもとであり禁止
- **各質問には自分の推奨回答を理由付きで添える**（例：「私のおすすめは○○です。理由は△△だからです。いかがですか？」）
- **コードベースを調べれば分かる事実は、質問せず自分で調べる**。ただし**判断はユーザーのもの** — 判断が必要な点は必ず1つずつユーザーに問い、回答を待つ
- **ユーザーが「共通理解に達した」と確認するまで、次の Step（要件メモ化）に進まない**

**質問の起点となる枝（ここから回答に応じて依存関係を辿り、深掘りする）：**

1. 目的 — なぜこの機能が必要か。何が解決されれば成功か
2. 利用者 — 誰が・どんな頻度で使うか
3. 主要ユースケース — 代表的な操作の流れ。例外的な流れはあるか
4. スコープ外 — やらないこと。将来に回すこと
5. 受け入れ条件の種 — 「できた」をどう判定するか（テストで検証できる形の候補）
6. 既存機能への影響 — 変更・共存が必要な既存機能はあるか（コードベースで確認できる事実は自分で調べたうえで、判断だけを問う）

### Step 4: 要件メモの整理と保存

深掘り結果（または提示された要件そのまま）を以下の構成で整理し、ユーザーに内容を確認してもらってから `docs/要件/<機能名>_要件メモ.md` に保存する：

```markdown
# <機能名> 要件メモ

- 作成日: YYYY-MM-DD
- 深掘り: grilling 実施 / 簡易深掘り実施 / なし（提示のまま）

## 目的・背景
## 利用者
## 主要ユースケース
## スコープ外（やらないこと）
## 受け入れ条件の種
## 未決事項
## 参考資料
```

- ユーザーが明言していないことを発明して書かない。未確認の点は「未決事項」に置く
- 未決事項は Phase 1〜3 で解消される前提でよい（ここで全部を確定させようとしない）

### Step 5: 完了通知と次フェーズ案内

```
開発開始の受付が完了しました。
- 要件メモ: docs/要件/<機能名>_要件メモ.md
- 深掘り: <実施内容>
- 未決事項: N 件（Phase 1〜3 で解消します）

次は Phase 1（設計書作成）です。
「<機能名>の設計書を作って」とお声がけください（flow-phase1-design-doc が起動します）。
```

## 禁止事項

- 要件の提示を受けずに設計・実装フェーズへ進まない
- 深掘りの要否をユーザーに確認せず勝手に grilling を始めない
- 要件メモにユーザーが言っていないことを発明して書かない
- 本 skill 内で設計書を書き始めない（Phase 1 の責務）
- 「実装したい」という言葉だけを根拠に `flow-phase8-impl` を起動しない（承認済みテストがない場合は本 skill が受ける）
