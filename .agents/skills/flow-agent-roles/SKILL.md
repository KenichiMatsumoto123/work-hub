# 開発フロー 役割定義集（flow-agent-roles）

10フェーズ開発フローで fresh context のサブエージェントとして分離実行する役割の**正本**を格納する。特定ツールのカスタムエージェント形式に依存しない、プレーンな Markdown の役割ファイルとして管理する。

## 収録している役割

| 役割ファイル | 役割 |
|---|---|
| `roles/reviewer.md` | 独立レビュワー（Read 専用・fresh context。Critical / Major / Minor の3段階で findings を報告。設計書・テスト・実装のレビュー用） |
| `roles/fix-builder.md` | 修正ワーカー（レビューで報告された Critical / Major findings を修正。初回作成者とは別の fresh context で起動。デグレ防止規律つき） |
| `roles/test-builder.md` | テスト作成ワーカー（Red Phase） |
| `roles/impl-builder.md` | 実装ワーカー（Green Phase） |

**旧役割からの移行（2026-08-08 改訂）：** `adversarial-reviewer`（敵対的レビュワー）と `impl-reviewer`（実装レビュワー）は廃止し、`reviewer` に統合した。「敵対的」較正はやめ、実害のある欠陥を正確な severity で報告する通常較正に一本化。あわせてレビュー後の修正ループ用に `fix-builder` を新設した。

**疎結合の原則：** 役割ファイルは「何をする役割か」だけを定義し、開発フローのどのフェーズで使うかには言及しない。フェーズと役割の対応づけは呼び出し側（flow-phase 系 skill）が定義する。これにより、同じ役割を複数フェーズ・フロー外の単発作業でも再利用できる。

## 起動パターン（flow-phase 系 skill から参照される）

役割は必ず**メイン会話（司令塔）と分離された fresh context の新規サブエージェント**として起動する。メイン会話で役割を代行してはならない。

- ツールの汎用サブエージェント起動機能（Claude Code / Codex / Cursor 等）で新規エージェントを起動する
- プロンプトの冒頭で、該当する役割ファイルの**絶対パス**を指定し、「まずこのファイルを読み、以後そこに定義された役割・絶対的な制約・出力形式に完全に従うこと」を指示する
- ツール制限（Adversary の Read 専用等）は役割ファイル内の指示で担保する。ツール固有のカスタムエージェント定義は使用しない

起動プロンプトには役割ファイルのパスに加えて、作業対象（設計書・テスト・実装のパス）、レビュー観点や作業範囲、出力形式など、各 flow-phase skill が定める内容を含める。

## 変更時の注意

- 役割の規律（テスト変更禁止・最小限実装・Read 専用・肯定的要約の禁止等）を変更する場合は、この配下の役割ファイルを更新する。ツール固有のカスタムエージェント定義（`.claude/agents/` 等）は作らない（役割の内容が分散するため）
- 役割ファイルはプロジェクト固有の技術スタック（Vitest / Prisma / Next.js 等）への言及を含む。異なるスタックへ展開する際は該当箇所の調整が必要
