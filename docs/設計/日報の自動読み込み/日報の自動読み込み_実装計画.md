## Phase 5. テスト作成（Red Phase）

実施者: `test-builder`（fresh context）。司令塔は起動前の未決確認・観点表の AI 全件起案・Red 証拠の独立検証・E2E 候補カタログ追記。司令塔はテストコードを書かない。実装ロジックは書かない。

**ゲート:** 新規および書き換えたテストが現行実装（またはスタブ）で **FAIL**（期待値不一致）。矛盾しない既存テストは **PASS**。import エラーだけで落ちないこと。スタブ段階で PASS する新規テストはトートロジー疑いとして書き直す。

Phase 7 スキップのため、影響度トリガー該当分（本機能ではクリティカルパス E2E）は **AI起案方式**。`flow-review-policy` 1.5 のチェックリストを足場にする。結合(DB込み)の影響度トリガーは設計書どおり非該当なので、観点表 1 章に「該当なし（理由）」を明記する（無言の省略は不可）。AC-L10 / AC-L11 はモック SELECT がトートロジーになるための技術検証であり、test-builder が機械導出する。

未決事項は設計書上すべて決定済み。ワーカー起動前に追加質問は不要。ただし AC-L44 の「未認証呼び出しの実形状」は Phase 5 で記録し、列挙が足りなければ設計書へ追記する（F-008 / Q5）。追記が仕様変更になる場合だけ人間へ確認する。
