# 実績0hの保存 要件メモ

- 作成日: 2026-08-16
- 深掘り: 簡易深掘り実施（grilling skill 未導入のため、grilling の手法に準拠して司令塔が実施。1問ずつ・推奨案つきで6問）

## 目的・背景

親機能「工数実績の正規化保存」では、実績h の `parseFloat` 結果が `0.005` 未満の行（`"0"` ・負数・微小値を含む）をスキップし、`time_entries` もマスタも作らない。DB の `chk_hours_positive`（`hours > 0`）も、0.00 の格納を想定していない。

「予定していたができなかった」タスクも、集計の記録として残す必要がある。空欄（未入力）と、実績ゼロとして残した行は区別する。

本開発の目的は、**実績h が 0h の行も `time_entries` に記録として残る状態**を作ること。集計の見せ方（画面・帳票）は本開発のゴールに含めない。

## 利用者

- 本アプリの利用者本人（日報を入力する開発者）。親機能と同じ。

## 主要ユースケース

1. 利用者が日報入力画面でタスク行を入力し、実績h に `0` を入れて保存する（「予定していたができなかった」の表現）
2. 保存時、当該行は対象行として扱われ、マスタ解決のうえ `time_entries.hours = 0.00` が作られる
3. 実績h が空の行（予定h だけ入っている行を含む）は、今までどおり記録しない
4. すでに保存済みの日報は一括では取り込まない。再保存した日報だけ新しい判定が適用される

## 決定事項

深掘りで確定した方針。

| # | 論点 | 決定 |
|---|---|---|
| 1 | 目的 | 0h も集計の記録として残す。「予定していたができなかった」を残す |
| 2 | 記録のトリガー | 実績h に `0` を入れた行だけ記録する。予定h のみ・実績空は今までどおりスキップ |
| 3 | 0h の範囲 | `parseFloat` が **0 以上 24.005 未満**を記録する。`"0"` も `"0.004"` も `0.00`。負数はスキップ |
| 4 | 変更範囲 | 保存（`time_entries`）だけ変える。日報テキスト・月次表・`getProjectSummary` は触らない |
| 5 | 過去データ | バックフィルしない。これから保存・再保存した日報だけ |
| 6 | マスタ | 0h でも対象行なので、`h > 0` の行と同じ規則でマスタを解決・作成する（`time_entries.task_id` が必須なため） |

### 実装上の帰結（判断ではなく事実）

- `time_entries` の `chk_hours_positive`（`hours > 0`）は、`0.00` を入れるために変更が必要
- 0h も対象行になるため、名前長さ検証（255 文字超で保存全体失敗）と上限（`24.005` 以上で保存全体失敗）は現行どおり対象行に適用される

## スコープ外（やらないこと）

- 日報テキスト（`generateDailyReport`）・月次工数表・`getProjectSummary` の表示変更
- 既存 `daily_reports.raw_data` から 0h 行を `time_entries` へ一括バックフィル
- 予定h のみ（実績空）の行を 0h として記録すること
- 負数の実績h を記録すること
- 予定工数（`schedule_entries`）への書き込み
- 集計画面・帳票の新規追加

## 受け入れ条件の種

テストで検証できる形の候補。Phase 1〜3 で設計書の受け入れ条件として確定させる。

1. 実績h が `"0"` / `"0.0"` / `"0h"` の行を保存すると、`time_entries` が 1 件作られ `hours` は `0.00`
2. 実績h が `"0.004"` の行を保存すると、`hours` は `0.00`（丸め後ゼロ）
3. 実績h が空欄・空白のみ・`"abc"` の行は、今までどおり `time_entries` もマスタも作らない
4. 実績h が負数（`"-3"`）の行は、今までどおりスキップする
5. 予定h だけ入って実績h が空の行は、今までどおりスキップする
6. 0h の行でも、取引先・プロジェクト・タスクのマスタ解決は `h > 0` の行と同じ
7. 再保存で実績h を `7.5` → `0` にすると、対応する `hours` は `0.00` になる
8. 再保存で実績h を `0` → 空にすると、その行の `time_entries` は残らない
9. 日報テキスト・月次表・`getProjectSummary` は変更しない
10. 既存日報の一括バックフィルはしない
11. `24.005` 以上は今までどおり保存全体を失敗させる
12. 0h でも対象行になるので、名前が 255 文字超なら今までどおり保存全体を失敗させる
