# 本リポジトリでの読み替え（work-hub 固有）

`docs/開発プロセス/` に置かれたフロー正典・実践ガイドは、Next.js（App Router）+ Prisma + MySQL/MariaDB を前提に書かれている。本リポジトリはスタックが異なるため、**以下の対応表で読み替えて適用する。**フロー自体（フェーズ構成・レビュー方針・収束ループ・ゲート）は読み替えなしでそのまま適用する。

## スタック対応表

| 正典の記述 | 本リポジトリでの読み替え |
|---|---|
| Next.js（App Router） | TanStack Start + TanStack Router + Vite |
| Prisma / `prisma.$transaction` | Drizzle ORM / `db.transaction()` |
| MySQL・MariaDB | PostgreSQL（docker compose で起動。`npm run db:up`） |
| `npx prisma db push` | `npm run db:push`（drizzle-kit push） |
| Route Handler（`route.ts`） | `createServerFn` によるサーバー関数（`apps/web/src/server/functions/`） |
| 単一パッケージ構成 | npm workspaces のモノレポ（`apps/web` / `packages/shared`） |

## ディレクトリ・ファイル配置の読み替え

| 正典の記述 | 本リポジトリでの配置 |
|---|---|
| `__tests__/<対象>.test.ts` | **対象モジュールと同じ階層に `<対象>.test.ts`**（例: `src/lib/time-utils.ts` → `src/lib/time-utils.test.ts`）。`__tests__/` ディレクトリは作らない |
| `__tests__/<対象>.integration.test.ts` | 同じく対象と同階層に `<対象>.integration.test.ts` |
| E2E: `tests/*.spec.ts` | `apps/web/e2e/*.test.ts`（Playwright の `testDir` は `./e2e`） |
| `src/test/db-helpers.ts` | `apps/web/src/test/db-helpers.ts`（Drizzle + PostgreSQL 版。後述の注意あり） |
| 設定ファイル（vitest / playwright） | リポジトリルートではなく `apps/web/` 配下 |

## コマンドの読み替え

テストコマンドはリポジトリルートから実行する（ルートの package.json が `apps/web` に委譲している）。

| 用途 | コマンド | DB |
|---|---|---|
| 単体 + 結合（内部） | `npm run test` | 不要 |
| カバレッジ | `npm run test:coverage` | 不要 |
| 結合（DB込み） | `npm run test:integration` | 必要 |
| E2E | `npm run test:e2e` | 必要 |
| 型チェック | `npm run check-types` | 不要 |
| DB 起動・スキーマ反映 | `npm run db:setup` | — |

## lint について

**本リポジトリには linter（ESLint / Biome）が導入されていない。**フロー正典および Phase 10 の実行検証ゲートに登場する `npm run lint` は、本リポジトリでは**「該当なし」として扱い、`npm run check-types` を代替の静的チェックとする。**

linter を導入した場合は本ファイルを更新し、Phase 10 の実行検証項目に `npm run lint` を戻すこと。

## DB込み結合テストの重要な注意（正典との差異）

正典・実践ガイドは `truncateAllTables()` による全テーブル削除を前提にしているが、**本リポジトリでは全テーブル TRUNCATE を既定の手段にしない。**

理由：本リポジトリは環境変数の解決を `.env` 一本に統一しており（`apps/web/src/server/env.ts` の `resolveDatabaseUrl` が親ディレクトリを遡って `.env` を読む）、テストが開発用 DB に接続する運用になっている。ここで全テーブルを TRUNCATE すると、開発中の日報データが消える。

したがって DB込み結合テストでは：

- **テストが作成したデータだけを、対象を絞って削除する**（既存例: `apps/web/src/server/auth/auth.integration.test.ts` は、テスト用のメールアドレスに紐づく行のみを削除している）
- どうしても対象テーブルを空にする必要がある場合は、`apps/web/src/test/db-helpers.ts` の `truncateTables()` にテーブル名を**明示列挙**して呼ぶ（引数なしで全件消す API は用意していない）
- 開発用 DB とテスト用 DB を分けたい場合は、`DATABASE_URL` を環境変数で上書きして実行する（例: `DATABASE_URL=postgres://... npm run test:integration`）
